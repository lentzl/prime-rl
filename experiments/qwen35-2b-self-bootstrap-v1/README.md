# Qwen3.5-2B endogenous self-bootstrapping v1

This experiment builds toward SPADE in explicitly separated rungs. It does not
describe inference-time best-of-N as SPADE. The paper-aligned primary signal is
the return gap between paired Reasoning Agent rollouts with and without a
privileged hint generated by the same immutable 2B policy in an Environment
Designer role.

Rung 0 uses the existing frozen procedural generator as a safe executable
environment source. The 2B Environment Designer sees privileged task metadata
and writes a strategy hint without the exact answer. The 2B Reasoning Agent
then receives four independently seeded plays in each arm. Designer/oracle data
never enters the no-hint arm, and only the validated hint enters the hint arm.
At least four distinct asynchronous task keys must show positive regret of at
least 0.25 before gradients open.

The direct-control slice follows the owner's compute-boundary policy: a clean
in-context calculation and one clean coordinator-local IPython calculation are
both valid. Exact output and abstention from unnecessary child delegation remain
hard requirements. `direct-control-policy-amendment.json` records this
prospective correction; it does not lower the four-asynchronous-task gate.

The original `P` versus best-of-four `P+` comparison remains a secondary
inference-search baseline over the same discovery bank. It measures whether
extra sampling compute finds verified successes, but it is not the designer
learning signal.

The bounded one-task Rung 0 pilot did not find a positive frontier on the
immutable 2B start. Two admitted same-model hints changed latency and trace
behavior but produced zero hard-return regret; stricter contract-aware and
executable-skeleton hint generation then failed closed rather than emitting a
misowned or incomplete hint. The full matrix and all gradients remain closed.
`foundation-rung0-pilot-result.json` is the result ledger. The scaffold is
retained for a stronger future starting checkpoint.

The owner subsequently corrected the curriculum interpretation: the paper's
early environments are allowed to teach through strongly exposed action
structure and informative feedback, and its single-turn template reveals the
solution after truncation so the model can learn from failure. The curriculum
then becomes more state-gated and finely graded as the Reasoning Agent grows.
`environment-scaffolding-amendment.json` therefore adds a prospective E0-E4
fade schedule: solution replay after a failed attempt, exact action scaffolds,
partial scaffolds, ordinary nonleaking privileged hints, and finally unhinted
behavior. These train-gen-only contexts are never called ordinary hint regret
and never enter held-out evaluation.

The existing four-trajectory floor is unchanged. At least four distinct,
complete, error-free, lineage-valid asynchronous hard successes are required
before any gradient. The amendment itself authorizes zero optimizer updates;
it first opens only inference admission for the leaky curriculum.

The first E0 replay on the previously failed `natural_n1a_local` task transferred
the child result and exact terminal answer but not the coordinator control policy:
the model omitted handle retention and local work from its first call, attempted a
post-spawn tool action, and polled before finally producing the exact JSON. The hard
reward therefore remained zero. `environment-scaffolding-e0-result.json` freezes
that evidence. The next prospective admission starts with child-only `natural_n1a`
and the opt-in one-turn natural-yield environment mediation; the local-work variant
is retained as a later, stricter anti-overgeneralization rung.

The child-only follow-up E0 showed that simplifying the graph was not sufficient.
The model admitted the child but did not retain its handle; the child sampled an
ill-typed send, and the coordinator spent the remaining budget on follow-ups,
invented wait calls, sleeps, and status inspection. A late assigned duplicate
spawn failed because the original child still existed. The request scaffold then
fired incorrectly on that failed spawn, exposing a fail-closed bug that is now
covered by a regression requiring an explicit successful `RLMSpawnHandle` output.
`environment-scaffolding-e0-child-only-result.json` freezes the run. The next E0
iteration must move help into the environment's action/feedback boundary rather
than merely placing an exact solution in prose; no further admission should run
until that interaction-level scaffold is tested.

Only a positive hint-regret result opens gradients. Rung 1 is a fixed-pool
Reasoning Agent GRPO control trained through an adapter from the immutable 2B
start. It tests whether the measured frontier can improve held-out solver
behavior before the substantially more complex adaptive designer is built.
It must not be reported as full SPADE.

Rung 2 adds the defining adaptive components: a corpus-grounded Environment
Designer that emits executable reset()/step() programs and privileged hints;
syntax, instantiation, deterministic-reset, bounded-execution, reward, and
termination validation; a 200-record environment memory; paired hint/no-hint
rollouts; and shared-policy updates for the designer and solver roles. Rejected
programs are retained for audit and never executed outside the sandbox.

Evaluation uses a disjoint held-out task bank whose untouched baseline is
frozen before training. Adapter promotion is paired by exact task key and must
preserve infrastructure completeness. Q38 and R7 remain untouched. The exact
rung definitions and the prospectively corrected relationship to the initial
preregistration are frozen in `paper-alignment-addendum.json`.

## Persistent interaction loop

`scripts/q35_2b_spade_interaction_loop_v1.py` turns the interaction curriculum
into an append-only state machine. A failed strict probe increases environment
help by one rung and schedules a fresh train-gen bank instead of ending the
experiment. A source is admitted only with at least four complete qualifying
trajectories on four distinct task keys. Both the child and passive-yield
sources must be admitted under the same frozen candidate before the controller
authorizes one adapter-only optimizer step. After that update is recorded, the
controller freezes the new candidate and automatically schedules the next
stricter probes.

The JSONL event log is the durable source of truth. It is sequence-numbered and
hash-chained, records artifact hashes for every bank, and reconstructs the next
action without relying on an in-memory process. The controller never executes
an optimizer update itself; it emits a one-step authorization only after the
unchanged admission gates pass, and validates a bounded-update receipt before
advancing the candidate.

`scripts/run_q35_2b_spade_autonomous_loop_v1.py` is the resumable executor for
that state machine. It owns the operational sequence that was previously
manual: build or verify a no-answer bootstrap, run the exact planned probe,
summarize and record it, follow the controller's leak-strengthening decision,
export exactly four successful child and four successful coordinator branches,
perform at most the authorized one-step adapter update, validate the metrics and
base/adapter hashes, record the new candidate, and continue with its stricter
targets. A nonblocking file lock prevents two executors from owning the loop.
The hash-chained runner journal brackets external commands; complete artifacts
are verified and reused after restart, while incomplete evaluation or training
directories receive a fresh attempt suffix. The configured action, evaluation,
and update budgets bound one invocation, and a caller-supplied stop file provides
a clean boundary between actions. Neither mechanism can relax admission or
authorize a gradient.

The historical R6Y5 event predates adapter-path persistence, so its first runner
invocation additionally needs the absolute R6Y5 adapter directory through
`--initial-adapter-path`. Every adapter produced and recorded by the autonomous
executor carries a verified absolute path in the event log and no longer needs
that recovery argument.

The first two manually operated closed-loop updates produced R6Y4 and R6Y5. R6Y4 was produced from four
admitted `e0c25` child branches and four admitted capped-yield coordinator
branches. Its stricter probes failed closed, the controller independently
strengthened each environment, retained the five-trajectory capped-yield source,
and admitted five fresh `e0c2` child trajectories. One further bounded update
produced frozen R6Y5.

The first unattended invocation then completed the full R6Y5-to-R6Y6 cycle. It
ran six R6Y5 admission banks, automatically increased child help from `e0c25`
through `e0_full_actions`, increased yield help from uncapped `e0d3` to capped
`e0d2`, admitted 6 distinct child and 5 distinct coordinator trajectories,
exported four of each, and performed one finite bf16 LoRA step. It recorded R6Y6
with adapter SHA-256
`1c2bca885ddbab01f3d649c36386035f3c33ce82faad2fecce0f860c20da6dec`.
The same process then tightened the curriculum and admitted 5 fresh R6Y6
`e0c_natural_child` trajectories; its uncapped-yield probe admitted only 1, so
the next durable action is capped-yield recovery at index 4,010,100 with zero
optimizer steps authorized. The invocation stopped cleanly at its nine-action
budget after eight evaluations and one update. The dense base received zero
updates, failed or audit-invalid trajectories contributed zero rows, and the
four-distinct-trajectory floor was never relaxed. Exact hashes and the complete
transition inventory are frozen in
`spade-autonomous-r6y5-to-r6y6-checkpoint.json`.
